# 코딩 표준 (NGV 구현 지침)

이 스킬은 CLAUDE.md "구현 지침"을 그대로 반영한다. 대상: Python 3.14
구현, unittest 테스트.

## 문서 작성 스타일

단답형(개조식: 명사형 종결, 불필요한 서술어 생략).

## 0. 절차 개요

1. `tdd` 스킬을 로드하고 그 절차(Red-Green-Refactor)를 따른다.
2. 구현 대상 함수의 상세설계 함수 계약(`detailed-designer` 산출물:
   사전조건/사후조건/부작용/예외/시간제약)을 확인한다. 없으면 사용자에게
   알리고, 최소한 계약을 가정한 뒤 근거를 명시하고 진행한다.
3. 테스트 작성 → 최소 구현 → 품질 지표 실측(아래 "2. 품질 지표") →
   기준 미달 시 리팩터링 → 재측정, 기준 충족까지 반복.
4. Doxygen 주석 작성, 추적성(3장) 갱신.

## 1. 산출물

- 소스 코드: 프로젝트 소스 디렉터리(예: `src/`)에 배치, 모듈은
  `architecture-designer`/`detailed-designer` 산출물의 모듈 ID·경계를
  따른다.
- 테스트 코드: `tests/` 디렉터리, `unittest` 기반, 파일명 `test_*.py`.
- SBOM/FOSS 라이선스 목록: Python 의존성(외부 패키지) 추가 시
  `.claude/0_WP_Templates/Engineering/SoftwareDetailedDesignAndUnitConstruction/TPL-SBOM-001_Python 의존성 SBOM FOSS 라이선스 목록 템플릿.xlsx`
  복사본(예: `ENG-SBOM-001_Python 의존성 SBOM.xlsx`)을 함께 갱신한다.
  의존성 추가 없으면 이 절차 생략 가능.

## 2. 품질 지표 (필수 준수, CLAUDE.md 지정)

| 지표 | 기준 |
|---|---|
| 함수 라인수 | 순수 코드 라인(주석·공백 제외) 50라인 이하 |
| 함수 순환복잡도(Cyclomatic Complexity) | 10 이하 |
| 중복 코드 | 7라인 이하만 허용(8라인 이상 중복 금지) |
| 주석 | Doxygen 방식, 전체 코드 대비 20% 이상 |
| 함수명/변수명 | 3글자 이상, 낙타 표기법(camelCase) |

- **실측 필수**: 위 지표는 오픈소스 도구로 실제 측정한 뒤 통과 여부를
  보고한다. 임의로 "기준 충족"이라 단정하지 않는다.
  - 순환복잡도/라인수: `radon cc`, `radon raw` 등
  - 중복 코드: `pylint --duplicate-code` 또는 동급 오픈소스 도구
  - 스타일/네이밍: `flake8`/`pylint` 등으로 보조 확인
  - 이 머신에 도구가 없으면(예: Python 미설치) 설치 가능 여부를
    확인하고, 설치·실행이 불가능하면 "실측 불가 — 환경 확인 필요"로
    명시한다. 실측 없이 기준 충족을 주장하지 않는다.
- 기준 미달 함수는 리팩터링(분리/단순화)한다. 분리로 응집도가 깨지면
  안 되며, `architecture-designer`/`detailed-designer`의 책임 분리
  원칙을 따른다.

## 3. Doxygen 주석 규칙

- 모든 공개 함수/메서드에 최소 `@brief`, `@param`, `@return`을 작성한다.
- 사전조건/사후조건이 있는 함수는 `@pre`, `@post`도 작성해 상세설계
  함수 계약과 대응시킨다.
- 예외를 던지는 함수는 `@throws`(또는 동급 태그)로 조건을 명시한다.
- 전체 코드 대비 주석 비율 20% 이상을 실제 라인 수 기준으로 확인한다
  (도구 또는 수동 계산, 근거 제시).

## 4. 네이밍 규칙

- 함수명, 변수명은 3글자 이상, 낙타 표기법(`myValue`, `calcSpeed` 등).
- 축약으로 의미가 불명확해지는 이름(예: 2글자 이하 약어) 금지.
- 모듈/클래스명은 상세설계의 모듈 ID·명칭과 대응되게 정한다.

## 5. 추적성 — TPL-TRC-001 `Code` 컬럼

- `Upper Req | SW Req | Architecture | Detailed Design | Code | SWE.4 | SWE.5 | SWE.6 | Coverage`
  매트릭스의 `Code` 컬럼에 실제 구현 파일 경로/함수명을 기재한다.
- 코드 추가/변경 시 같은 작업 안에서 매트릭스를 함께 갱신한다. 상세설계
  함수 ID와 실제 함수명이 다르면 매핑을 명시한다.

## 6. 저작권 유의

A-SPICE/ISO 26262 **표준 원문**은 통째 인용 금지(구조·용어만 사용).
사용하는 오픈소스 도구의 라이선스는 SBOM 산출물에 기록하되, 도구
문서 원문을 통째로 복제하지 않는다.

## 7. 하지 말아야 할 것

- `tdd` 스킬을 로드하지 않고 구현부터 작성하는 것.
- 품질 지표를 실제 도구로 측정하지 않고 "기준 충족"이라 단정하는 것.
- 함수 라인수/순환복잡도 기준 초과를 알면서 방치하는 것.
- Doxygen 주석 없이 공개 함수를 구현하는 것.
- 3글자 미만 이름이나 스네이크/헝가리안 등 프로젝트 표기법과 다른
  네이밍을 사용하는 것.
- 코드 변경 후 추적 매트릭스(`Code` 컬럼) 갱신을 누락하는 것.
- 외부 패키지 추가 후 SBOM/FOSS 목록 갱신을 누락하는 것.
