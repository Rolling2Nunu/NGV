# 상세설계자 (Detailed Designer)

이 스킬은 A-SPICE PAM 4.1 SWE.3(Software Detailed Design and Unit
Construction)와 ISO 26262 Part 6 상세설계 원칙을 준수하는 SW 상세설계서를
작성하기 위한 절차와 규칙을 정의한다. `architecture-designer`가 정의한
컴포넌트를 실제 모듈/함수 단위로 구체화하는 단계.

## 문서 작성 스타일

단답형(개조식: 명사형 종결, 불필요한 서술어/수식어 생략). 예: "책임: 속도
필터 계산", "사전조건: 입력값 0 이상". ID, 수치, 근거 등 필수 정보는
생략 금지.

## 0. 템플릿 — 확정, 실제 파일 사용

정식 템플릿 확정됨(사용자 승인으로 교육용 저작권 표시 무시하고 사용).
경로(저장소 루트 `D:\NGV\NGV` 기준):

- `.claude/0_WP_Templates/Engineering/SoftwareDetailedDesignAndUnitConstruction/TPL-SWE3-002_상세설계 UML 및 호출관계 템플릿.drawio`
- `.claude/0_WP_Templates/Engineering/SoftwareDetailedDesignAndUnitConstruction/TPL-SBOM-001_Python 의존성 SBOM FOSS 라이선스 목록 템플릿.xlsx` — Python 의존성 사용 시만 해당(참고, 본 스킬 필수 범위 아님)
- `.claude/0_WP_Templates/Engineering/Traceability/TPL-TRC-001_양방향 요구사항 추적 매트릭스 템플릿.xlsx`

**산출물 생성 절차**: 마크다운 신규 작성 대신 위 docx/drawio 템플릿을
산출물 경로로 복사 후 `docx` 스킬 및 drawio XML 직접 작성으로 채운다.
파일명은 등록부 ID 규칙(예: `ENG-SWE3-001_SW 상세설계서.docx`,
`ENG-SWE3-002_상세설계 UML 및 호출관계.drawio`).

## 1. 저작권 유의

A-SPICE PAM 4.1과 ISO 26262 **표준 원문**(조항 번호, 정확한 문구, 표
전문)은 VDA/intacs와 ISO 저작물 — 통째 인용 금지. MISRA 등 코딩 표준
원문도 동일하게 통째 인용 금지, 표준 채택 여부/명칭만 언급.
(0_WP_Templates 구조 자체는 사용자 지시로 무시하고 사용.)

## 2. 문서 구조 — TPL-SWE3-001 목차(확정, 15장)

1. 목적 및 범위
2. 모듈 분해(아키텍처 컴포넌트 → 모듈/유닛 매핑)
3. 상세 호출관계
4. 공통 자료형
5. 핵심 함수 계약(입력/출력/사전조건/사후조건/부작용/예외/시간제약)
6. 핵심 알고리즘
7. 정책 의사결정표
8. 상태전이 상세
9. Web/API 상세
10. 오류와 방어 동작
11. 코딩 및 검증 규칙
12. 단위와 요구사항 할당
13. 구현 경계
14. 추적성
15. 참고자료

공통 골격(모든 TPL-*.docx 동일): 표지 → 문서통제(변경이력표, 작성검토
승인상태표) → 목차 → 본문.

## 3. 선행 조건 확인

- 상세설계는 아키텍처 설계(`architecture-designer` 산출물)를 구체화하는
  단계 — 작업 전 대상 컴포넌트의 아키텍처 설계서·인터페이스 정의를
  확인한다. 없으면 사용자에게 알리고, 최소한 컴포넌트 책임/인터페이스
  가정을 명시한 뒤 진행(임의로 새 컴포넌트를 지어내지 않는다).
- 대상 요구사항(REQ-SW-F-*, REQ-SW-NF-*)과 TPL-TRC-001 추적 매트릭스를
  확인해 이 설계가 할당받는 요구사항 범위를 파악한다.

## 4. 모듈 분해 및 호출관계 (2~3장)

- 아키텍처 컴포넌트를 모듈/유닛으로 분해하고, 각 모듈에 고유 ID·책임을
  부여한다(응집도 근거: 단일 책임 유지).
- 모듈 간 호출관계는 아키텍처에서 정의한 인터페이스를 벗어나지 않는다
  (컴포넌트 경계를 넘는 호출은 반드시 아키텍처 인터페이스 경유, 우회
  호출 금지 — 낮은 결합도 원칙 계승).
- 호출관계 다이어그램은 **.drawio**로 작성(TPL-SWE3-002 스캐폴드 기반,
  실제 호출 그래프/클래스 다이어그램 표기로 채움).

## 5. 핵심 함수 계약 (5장, 필수)

각 핵심 함수/메서드마다 다음을 명시한다(함수 단위의 "인터페이스" —
모듈 간 통신은 이 계약을 통해서만 이루어진다).

- 함수 ID/이름, 소속 모듈
- 입력 파라미터(자연어 설명 + 타입/단위/범위)
- 출력/반환값(자연어 설명 + 타입/단위/범위)
- 사전조건(Precondition): 호출 전 보장돼야 하는 상태
- 사후조건(Postcondition): 정상 종료 시 보장하는 상태
- 부작용(Side effect): 전역/공유 상태 변경 여부(가급적 없음을 원칙으로,
  있으면 명시)
- 예외/오류 처리: 오류 코드, 예외 조건과 처리 방식
- 시간 제약: 실행 시간 한도, 실시간 제약(해당 시)

## 6. 핵심 알고리즘 / 정책 의사결정표 / 상태전이 (6~8장)

- 알고리즘은 의사코드 또는 단계 목록으로 서술, 요구사항의 수용기준과
  대응되는지 확인.
- 정책/분기 로직이 복잡하면 결정표(조건 조합 × 결과)로 표현.
- 상태 기반 모듈은 상태전이표 또는 .drawio State Machine Diagram으로
  표현, 아키텍처 8장(상태 전이)과 정합성 유지.

## 7. 오류와 방어 동작 (10장)

- 함수 계약의 예외/오류 처리를 모듈 수준에서 종합: 입력 검증, 경계값
  처리, 실패 시 안전 상태(fail-safe/fail-operational) 정의.
- ISO 26262 관련 방어 로직(예: 이중화, 타임아웃 감시)은 근거(아키텍처
  9장 오류격리 설계, HARA/안전요구사항)와 함께 기재, 근거 없으면 "근거
  문서 필요"로 표시.

## 8. 코딩 및 검증 규칙 (11장)

- 프로젝트가 채택한 코딩 표준(예: MISRA C/C++ 등)이 있으면 명칭만
  기재하고 표준 원문은 인용하지 않는다. 미정이면 "코딩 표준 미정 —
  사용자 확인 필요"로 표시, 임의로 특정 표준을 강제하지 않는다.
- 이 장의 함수 계약(사전/사후조건)이 SWE.4 단위시험 명세(TPL-SWE4-001)의
  기대 결과 근거가 됨을 명시(범위는 SWE.4 스킬 몫, 여기서는 연계만 기술).

## 9. SOLID / 응집도-결합도 원칙 (모듈·함수 단위 계승)

- `architecture-designer`의 원칙을 모듈/함수 단위로 계승: 단일 책임,
  낮은 결합(전역 상태 최소화, 모듈 간 직접 내부 접근 금지), 인터페이스
  분리(함수 계약을 목적별로 분리).
- 여러 구현 대안이 가능한 핵심 알고리즘/모듈 구조가 있으면, 대안과
  선택 근거(성능/복잡도/안전성)를 짧게 기록한다(아키텍처처럼 사용자
  승인 대기 절차까지는 필수 아님 — 설계 근거 기록으로 충분).

## 10. 추적성 — TPL-TRC-001 기준(확정)

- `.claude/0_WP_Templates/Engineering/Traceability/TPL-TRC-001_...` 복사본
  (`ENG-TRC-001_양방향 요구사항 추적 매트릭스.xlsx`) 사용, 컬럼:
  `Upper Req | SW Req | Architecture | Detailed Design | Code | SWE.4 | SWE.5 | SWE.6 | Coverage`
- 이 스킬은 `Detailed Design` 컬럼을 채운다(모듈/함수 ID 기재).
- 12장(단위와 요구사항 할당)에도 모듈-요구사항 매핑을 명시적으로 기록.
- 상세설계 변경 시 같은 작업 안에서 매트릭스 함께 갱신.

## 11. 하지 말아야 할 것

- 아키텍처에 없는 컴포넌트/인터페이스를 임의로 새로 만들어 상세설계에
  반영하는 것.
- 모듈 간 통신을 함수 계약 없이(직접 상태 접근으로) 설계하는 것.
- ISO 26262/A-SPICE/코딩 표준 **원문**을 통째로 인용하는 것.
- 근거 없이 코딩 표준이나 ASIL 관련 방어 로직을 확정하는 것.
- 상세설계 변경 후 추적 매트릭스(TPL-TRC-001 기반) 갱신을 누락하는 것.
- 실제 템플릿 파일(docx/drawio) 대신 임의의 마크다운 구조로 산출물을
  대체하는 것.
